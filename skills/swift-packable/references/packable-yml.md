# `packable.yml` reference

The file sits next to the client's `Package.swift` (or pass `--config <file>` to `generate`/`use`). Relative paths resolve against the directory holding `packable.yml`.

```yaml
cache: .packable-cache                     # optional
dependencies:
  ShowcaseKit:
    mode: binary                           # source (default) | binary
    source: { path: ../ShowcaseKit }
    binary: { path: ../ShowcaseKit-binary }   # optional; built on demand when missing
  Alamofire:
    source: { url: https://github.com/Alamofire/Alamofire.git, from: 5.9.0 }
    binary: { url: https://github.com/example/Alamofire-binary.git, exact: 5.9.1 }
  Logging:
    mode: binary
    source: { url: https://github.com/apple/swift-log.git, exact: 1.6.1 }
    # No `binary:`, so these shape the on-demand build:
    products: [Logging]
    platforms: [ios, ios-simulator]
    linkage: dynamic
    skip-interface-verification: true
    disable-library-evolution: false
    debug-info: false                      # or debug-objects: true, not both
```

Write each dependency as a block mapping (`Name:` on its own line, keys indented below). `use` edits the `mode:` line as text, keeping comments and layout, and adds `mode:` when it's missing; it can't edit a dependency written in flow style (`Name: { … }`) and fails with ``Couldn't find `Name:` (in block style) under `dependencies:` ``. Locations may be flow style. Names may be quoted (`"My-Kit":`).

## Top level

| Key | Required | Meaning |
|---|---|---|
| `dependencies` | yes | Map of name → dependency. The name is what `use <names>` and `packable("<product>", from: "<name>")` refer to. |
| `cache` | no | Where on-demand binaries go. Default: `.build/packable-cache` in the package (kept when `use` clears `.build`; `swift package clean` deletes it, so rerun `generate`). `Package.swift` refers to it by a path relative to the package. |

## Dependency

| Key | Required | Default | Meaning |
|---|---|---|---|
| `mode` | no | `source` | `source` or `binary`. `swift-packable use` rewrites it. |
| `source` | yes | — | A location (below). |
| `binary` | no | built on demand | A location of a prebuilt binary package, generated by this tool or released at a URL. Used as is. |
| `products` | no | all library products | On-demand builds only. In binary mode only these products exist. |
| `platforms` | no | source manifest's platforms | On-demand builds only. `macos`, `maccatalyst`, `ios`, `ios-simulator`, `tvos`, `tvos-simulator`, `watchos`, `watchos-simulator`, `visionos`, `visionos-simulator`; SDK aliases `iphoneos`, `iphonesimulator`, `appletvos`, `appletvsimulator`, `watchsimulator`, `xros`, `xrsimulator`. Anything else: `Unknown platform '<name>' in packable.yml.` |
| `linkage` | no | `static` | On-demand builds only. `static` or `dynamic`; cached separately. |
| `skip-interface-verification` | no | `false` | On-demand builds only. |
| `disable-library-evolution` | no | `false` | On-demand builds only. Builds without `-enable-library-evolution` and without `.swiftinterface`s; clients must use the same compiler. |
| `debug-info` | no | `false` | On-demand builds only, like `--debug-info`: static frameworks keep DWARF so lldb/xcsrclink can map sources. Static only; cached separately (`-debug-info` suffix). |
| `debug-objects` | no | `false` | On-demand builds only, like `--debug-objects`: static frameworks stay lean and their debug objects go to the cache entry's `debug-objects/` folder. Static only; cached separately (`-debug-objects` suffix). Setting it with `debug-info` fails: `<file>: <name> sets both debug-info and debug-objects; choose one.` |

## Locations

Exactly one of `path` or `url`. A `path` takes no version requirement; a `url` takes exactly one.

| Form | Generates |
|---|---|
| `{ path: ../Kit }` | `.package(path: "../Kit")` (rewritten relative to the package) |
| `{ url: …, from: 1.2.0 }` | `.package(url: …, from: "1.2.0")` |
| `{ url: …, exact: 1.2.0 }` | `.package(url: …, exact: "1.2.0")` |
| `{ url: …, up-to-next-minor: 1.2.0 }` | `.package(url: …, .upToNextMinor(from: "1.2.0"))` |
| `{ url: …, branch: main }` | `.package(url: …, branch: "main")` |
| `{ url: …, revision: 4f2c1e0 }` | `.package(url: …, revision: "4f2c1e0")` |

The package name used in `.product(name:package:)` is the location's last path component without `.git`.

## Commands and options

```bash
swift-packable generate [--package-path <dir>] [--config <file>] [--rebuild] [-v]
swift-packable use source|binary <names…> | --all [--no-clean] [--package-path <dir>] [--config <file>] [--rebuild] [-v]
```

| Option | Meaning |
|---|---|
| `--package-path` | Client package whose `Package.swift` gets the block. Default `.`. |
| `--config` | Default `<package-path>/packable.yml`. |
| `--rebuild` | Rebuild on-demand binaries even when cached ones are current; move remote sources to the newest allowed version. |
| `-v, --verbose` | Stream build output. |
| `--all` | `use` only: every dependency. Names and `--all` are mutually exclusive, one is required. |
| `--no-clean` | `use` only: keep `.build`. |

`use` changes only `mode:`, then runs `generate`; if that fails, `packable.yml` is restored. An undeclared name fails with `'<name>' isn't declared in packable.yml. Declared: …`. When nothing changes it prints `Already <mode>: …` and doesn't clean.

## The generated block

`generate` writes this between `// packable:begin` and `// packable:end` (after `import PackageDescription` the first time). Don't edit it; change `packable.yml` and rerun.

```swift
// packable:begin
// Generated by `swift-packable generate` from packable.yml; don't edit by hand.
// Switch modes with `swift-packable use source|binary <name>`.
// swiftformat:disable all
// ShowcaseKit: binary

let packableDependencies: [Package.Dependency] = [
  .package(path: ".build/packable-cache/ShowcaseKit/local/ShowcaseKit-binary"),
]

/// A product of a dependency declared in packable.yml, in its current mode.
func packable(_ product: String, from dependency: String) -> Target.Dependency {
  let packages: [String: String] = [
    "ShowcaseKit": "ShowcaseKit-binary",
  ]
  return .product(name: product, package: packages[dependency] ?? dependency)
}
// swiftformat:enable all
// packable:end
```

- `packableDependencies`: one `.package(…)` per entry, in name order. Source mode uses `source:`; binary mode uses `binary:` or the on-demand build's folder.
- `packable(product, from: name)`: `product` is a library product, `name` the `packable.yml` key. It maps to the current mode's package name (`ShowcaseKit` from source, `ShowcaseKit-binary` built on demand, else the `binary:` location's last component), so targets must use it rather than `.product(…)`. An unknown name is passed through as the package name.

The rest of the manifest uses only those two names:

```swift
dependencies: packableDependencies,
targets: [.target(name: "App", dependencies: [packable("ShowcaseKit", from: "ShowcaseKit")])]
```

## Cache layout

```
<cache>/<name>/local[-dynamic|-debug-info|-debug-objects]/<name>-binary/          # local source; rebuilt when its build checksum changes
<cache>/<name>/<tag>[-dynamic|-debug-info|-debug-objects]/<name>-binary/          # remote source at a tag
<cache>/<name>/rev-<12 chars>[-dynamic|-debug-info|-debug-objects]/<name>-binary/ # remote source at a branch or revision
<cache>/<name>/<entry>-debug-objects/debug-objects/                     # debug objects, next to that entry's binary
<cache>/<name>/resolver/                               # throwaway package that resolves the remote source
```
