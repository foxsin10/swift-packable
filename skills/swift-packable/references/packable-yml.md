# `packable.yml` reference

The file sits next to the client's `Package.swift` (or pass `--config <file>` to `generate`/`use`). Relative paths resolve against the directory holding `packable.yml`.

```yaml
cache: .packable-cache                     # optional
dependencies:
  ShowcaseKit:
    mode: binary                           # source (default) | binary
    source: { path: ../ShowcaseKit }
    binary: { path: ../ShowcaseKit-binary }   # optional; built on demand when missing
    linkage: dynamic
  Alamofire:
    source: { url: https://github.com/Alamofire/Alamofire.git, from: 5.9.0 }
  Logging:
    mode: binary
    source: { url: https://github.com/apple/swift-log.git, exact: 1.6.1 }
    products: [Logging]
    platforms: [ios, ios-simulator]
    skip-interface-verification: true
```

## Top level

| Key | Required | Meaning |
|---|---|---|
| `dependencies` | yes | Map of name → dependency. The name is what `use <names>` and `packable("<name>", from:)` refer to. |
| `cache` | no | Where on-demand binaries go. Default: `.build/packable-cache` in the package (kept when `use` clears `.build`; `swift package clean` deletes it, so rerun `generate`). `Package.swift` refers to it by a path relative to the package. |

## Dependency

| Key | Required | Default | Meaning |
|---|---|---|---|
| `mode` | no | `source` | `source` or `binary`. `swift-packable use` rewrites it. |
| `source` | yes | — | A location (below). |
| `binary` | no | built on demand | A location of a prebuilt binary package, generated by this tool or released at a URL. Used as is. |
| `products` | no | all library products | On-demand builds only. |
| `platforms` | no | source manifest's platforms | On-demand builds only. `macos`, `maccatalyst`, `ios`, `ios-simulator`, `tvos`, `tvos-simulator`, `watchos`, `watchos-simulator`, `visionos`, `visionos-simulator`; SDK aliases `iphoneos`, `iphonesimulator`, `appletvos`, `appletvsimulator`, `watchsimulator`, `xros`, `xrsimulator`. |
| `linkage` | no | `static` | On-demand builds only. `static` or `dynamic`; cached separately. |
| `skip-interface-verification` | no | `false` | On-demand builds only. |

## Locations

Exactly one of `path` or `url`. A `path` takes no version requirement; a `url` takes exactly one.

| Form | Generates |
|---|---|
| `{ path: ../Kit }` | `.package(path: "../Kit")` (rewritten relative to the package) |
| `{ url: …, from: 1.2.0 }` | `.package(url: …, from: "1.2.0")` |
| `{ url: …, exact: 1.2.0 }` | `.package(url: …, exact: "1.2.0")` |
| `{ url: …, up-to-next-minor: 1.2.0 }` | `.package(url: …, .upToNextMinor(from: "1.2.0"))` |
| `{ url: …, branch: main }` | `.package(url: …, branch: "main")` |
| `{ url: …, revision: 4f2c1e0 }` | `.package(url: …, revision: "4f2c1e0")` |

The package name used in `.product(name:package:)` is the location's last path component without `.git`.
